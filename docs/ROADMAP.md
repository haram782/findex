# Findex 제품 로드맵

## 제품 방향

Findex는 노량진수산시장 경락 데이터를 거래소 화면처럼 빠르게 탐색하면서, 어종별
기본 정보와 시장 소식을 함께 축적하는 수산물 데이터 워크스페이스를 지향한다.

핵심 화면 원칙은 다음과 같다.

- 현재 보고 있는 어종을 화면 상단에서 즉시 알 수 있어야 한다.
- 여러 어종을 선택하면 대표 어종과 추가 선택 수를 간결하게 표시한다.
- 시세 탐색과 어종 정보, 관련 소식을 같은 맥락 안에서 전환한다.
- 화이트/다크 테마와 관심어종을 브라우저에 보존한다.
- 장기 시계열은 기간과 집계 단위를 분리해 탐색하고 확대·이동할 수 있어야 한다.

## Phase 1 — 거래 화면 기본 경험

이번 작업에서 구현한다.

- Upbit 레이아웃을 참고한 선택 어종 요약 영역
  - 1개: `금태`
  - 2개: `금태, 양태`
  - 3개 이상: `금태 외 2`
- 모든 어종에 공통으로 사용하는 임시 이미지
- `시세`, `어종 정보`, `시장 소식` 탭
  - 정보와 소식은 후속 데이터 연동 전까지 빈 상태와 예정 기능을 명확히 안내
- 화이트/다크 테마 전환과 브라우저 저장
- 어종 관심 등록과 관심어종 전용 목록
- 기간 범위: 1주, 20일, 3개월, 1년, 전체
- 집계 단위: 일봉, 주봉, 20일봉
- 마우스 휠/핀치 확대, 드래그 이동, 확대 초기화

### 시계열 집계 규칙

원본 일별 데이터를 브라우저에서 날짜 정렬 후 단일 순회로 집계한다.

- 평균가: `거래대금 합계 / 수량 합계`
- 고가: 구간 내 최고가
- 저가: 구간 내 최저가
- 수량과 거래대금: 구간 합계

현재 선택은 최대 5개이고 5년치 일 데이터도 수천 건 수준이므로 클라이언트
O(n log n) 집계가 충분하다. 공개 서비스에서 데이터 규모가 커지면 API의 서버 집계와
캐시로 이동한다.

## Phase 2 — 어종 정보와 LLM Wiki

- `species_profile` 저장 모델과 조회 API
- 제철, 주요 산지, 특징, 취급 주의사항(가시·독성 등 위험 요소 중심, 보관법·조리용
  손질 절차는 다루지 않음)을 구조화해 저장. 대표 이미지는 필드만 있고 아직 미사용
- LLM 초안 생성 시 출처 URL, 생성 모델, 생성 시각, 검수 상태를 함께 기록
- **발행 흐름(2026-07-29 결정)**: 초안 작성과 무관한 독립된 검증 단계(별도 컨텍스트의
  에이전트가 `source_urls`를 다시 열어 문장 단위로 대조)를 거쳐 `verification_status`를
  기록한다. 검증 통과(`verified`)면 자동으로 발행되고, 문제 발견(`flagged`)이면 이미
  발행된 상태였더라도 즉시 초안으로 되돌아간다. 사람의 역할은 문장별 재검증이 아니라
  검증 결과·플래그 사유를 확인하는 수준으로 줄어든다
- 수정 이력과 마지막 검수 시각 표시

LLM이 생성한 내용을 사실 데이터처럼 바로 노출하지 않는다. 출처가 없는 문장은
발행 대상에서 제외하고, 가격 데이터와 설명 콘텐츠의 책임을 분리한다. 다만 "출처가
있다"는 것과 "출처가 그 문장을 실제로 뒷받침한다"는 것은 다르다 — 파일럿 5종 전체가
독립 검증에서 flagged된 사례(2026-07-29)처럼, 초안 작성자가 스스로 확인하지 못한
불일치(없는 근거로 단정, 출처 간 모순 방치, URL 필자 닉네임을 사실로 오인 등)가
실제로 발생하므로 발행 전 독립 검증을 반드시 거친다.

## Phase 3 — 시장 소식 수집

- 어종명과 동의어 기반 기사 검색
- RSS나 정식 검색 API를 우선 사용하고, 직접 크롤링은 이용약관과 robots 정책 확인 후 적용
- 원문 URL, 매체, 발행 시각, 수집 시각 저장
- URL 정규화와 제목 유사도로 중복 제거
- 어종 매핑 신뢰도가 낮은 기사는 검수 대기
- 수집 실패는 기존 시세 cron과 분리해 재시도와 관찰이 가능하도록 운영

화면 탭 이름은 기능이 기사 외 보고서·시장 공지까지 확장될 수 있도록 `시장 소식`을
기본으로 사용한다.

## Phase 4 — 장기 데이터와 운영

- 최근 5년 백필 완료와 진행률 화면
- 주봉·20일봉 서버 집계 및 응답 캐시
- 데이터 누락, 수집 지연, 파서 변경 감지 알림
- 어종 정보·기사 수집의 출처별 상태와 실패율 관찰
- 공개 서비스 전환 시 인증, rate limit, 배포·백업 정책 확정

## Phase 5 (가칭) — 날씨·산지 기반 시세 영향 분석

- 날씨·산지별 어획량 변동이 시세에 미치는 영향을 분석한다.
- 날씨 예보를 시세 변동 예측에 활용한다(상관관계 추론은 LLM의 영역으로 본다).
- `PriceRecord.origin`, `species_profile.main_origins`를 조인 축으로 활용할 수 있다.
- 날씨 데이터 수집, 어획량-가격 상관 분석, 예측 모델 설계는 착수 시점에 별도로 정한다.

## 추적 방식

- Phase마다 GitHub Issue를 만들고 이 문서를 기준 문서로 연결한다.
- 실제 구현은 기능별 하위 Issue로 나누고 완료 조건과 테스트 결과를 남긴다.
- 코드와 문서가 함께 변경되면 동일 커밋 또는 동일 Phase 브랜치에서 관리한다.
